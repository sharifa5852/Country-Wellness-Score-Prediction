_Generated by CELL 25 on 2026-11-06 from the saved metadata files. Do not edit by hand; re-run CELL 25._

## 1. Terminology and target

- The repository name says *Wellness*; every column and metric uses **Happiness**. They are the same quantity here: the World Happiness Report **Cantril ladder** score (0-10, self-reported life evaluation).
- **Target** `HappinessScore_target` = happiness score in calendar year **t+1**. It is regression (MAE, RMSE, R2). It is **never scaled or imputed**, so errors are in score points.

## 2. Temporal setup (why this dataset differs from `data/processed`)

- One row = one country at **origin year t**. Features use years t, t-1, t-2. The target is year t+1.
- Strategy **STRICT**: a row exists only if the real observations for t-2, t-1, t and t+1 all exist (exact calendar-year joins). Year 2013 is absent for every country, so no feature or target is ever invented across that gap.
- The old pipeline used row-position `shift()`, which silently linked 2012 to 2014 and 2014 to 2012. See `results/tables/temporal_alignment_audit_by_year.csv`.

A training row with origin 2021 has target year 2022. That is not leakage: at the 2022 forecast origin, the 2022 outcome is known history. Validation targets are 2023 and test targets are 2024 (the test origin year is 2023).

## 6. Preprocessing decisions

- **Missing covariates:** forward-fill from the same country's last REAL observation, maximum 2 calendar years, past values only. Interpolation is not used: interpolation would use values after the forecast origin.
- **Never imputed:** `HappinessScore`, `GDPPerCapita_WB`, `HappinessScore_target`.
- **Flags:** `UnemploymentRate_WB_was_missing`, `InternetAccessPct_WB_was_missing`, `HealthExpenditurePctGDP_WB_was_missing` = 1 where the value was originally missing at year t.
- **Remaining NaN:** median imputed using TRAINING rows only (CELL 23).
- **Known limitation:** Hong Kong and Puerto Rico have no health expenditure data at all; their value is the training median plus flag=1.
- **Fit rows:** train only (origin year <= 2021) (842 rows). Validation and test only use `transform`.
- **GDP:** natural log, GDP verified > 0.

## 7. LSTM representation (different from the tabular lag matrix)

- Tabular models see **one flat row** of 18 independent columns. The model does not know that `*_lag2`, `*_lag1` and the current column are consecutive years of the same variable.
- The LSTM sees a **sequence** with shape (samples, timesteps, features) = (n, 3, 5): the same 5 base features at t-2, t-1, t, in time order, and it carries a hidden state from step to step.
- LSTM features: `HappinessScore`, `log_GDPPerCapita_WB`, `UnemploymentRate_WB`, `InternetAccessPct_WB`, `HealthExpenditurePctGDP_WB`.
- LSTM imputer/scaler are fit on the stacked TRAIN steps (all from years <= 2021) and saved separately from the tabular ones.

## 9. Limitations to cite

- The test set is a single origin year (2023 -> 2024), so test metrics have large sampling uncertainty.
- Strict alignment shrinks the training set (the old pipeline had more rows, but with misaligned lags).
- Feature importance and coefficients describe prediction, not causation.
